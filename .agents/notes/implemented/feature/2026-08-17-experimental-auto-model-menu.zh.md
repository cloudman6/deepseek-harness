# Agent Note: 实验性 Auto 模型菜单

Status: implemented

[English](2026-08-17-experimental-auto-model-menu.md) | 中文

## 问题

外部 Auto 插件可以在 Host 边界选择提供方、模型和可选推理强度，但用户需要把实际请求路由与独立的任务处理级别区分开，并理解该路由来自 AA 证据还是已配置的深度 fallback。浏览器自行维护的标签或推断状态可能与持久化 Host 决定不一致。

## 决策

维护者 fork 以可选 `dshAutoMode` Session 投影扩展现有 `conversation.input.model` 入口。投影存在时，根菜单把 Auto 放在 Model 和 Effort 之前，用标准对勾图标标记启用行，并显示有效模型及提供方支持时的推理强度。它单独显示 Host 持有的轻量、常规或深度任务处理级别，并把 AA 数据或已配置深度 fallback 标为路由依据。AA 匹配决定会显示确切快照 id；已配置 fallback 会明确说明 AA 快照不适用，而不会暗示存在证据匹配。紧凑触发器在投影路由前添加 Auto；明确的“实际选择”标签把 Host 选择事实与下方手工控件区分开。UI 把 AA 路由描述为未经项目 Benchmark 验证的启发式机制。

初始投影选择只建立显示状态，不播放动画。之后出现新的决定时，Host 投影会同时携带紧邻的前一条决定和有效决定。客户端只把发生变化的模型、推理 effort 或任务处理级别在 1.2 秒内从前值滚动到有效值。Auto 和每个变化目标在值到达期间使用 DSH 业务蓝，随后呼吸两次，再恢复周围标签颜色。因此只有级别变化时，仅级别和 Auto 标记播放动画，路由保持静态。`prefers-reduced-motion` 会取消位移动画，同时保留最终值和更新文字。

外部插件持有 Auto 状态和决定。它追加 `dsh-auto-mode/mode` 与 `dsh-auto-mode/selection` 事件，经 `ctx.sessionProjections` 折叠，并注册 `/auto [off]`。schema v2 selection 携带任务处理级别和路由依据，不再发布原型 `fast`／`standard`／`strong` tier。维护者客户端在回放现有 Session 时仍会映射 schema v1 tier，但不会再发出它们。每条发生变化的持久化选择都会在产生结果的助手回复之前、事件自身的持久位置成为一条聊天时间线路由事实。变化字段显示前值、箭头和业务蓝有效值；未变化字段只显示有效值。路由没有 effort 维度时，UI 会省略该行，而不是虚构提供方 effort。

模型选择客户端经现有命令 Remote 调用 `/auto` 或 `/auto off`。无论通过 composer 还是 `/model` 选择手工模型或推理强度，客户端都会先停用 Auto，再提交普通 `session.selectModel` 请求。投影缺席时，标准模型菜单的行为保持不变；已寻址 subagent 会话仍不可用。当建议性模型目录缺少 Auto 的有效路由时，触发器仍显示投影中的确切模型与推理强度 id，而不会隐藏请求事实。

该集成仅是维护者专用、固定 fork 的载体。它不会把 Auto 策略加入 DSH Core，不进入默认组合，不宣称官方兼容，也不会把 AA 数据当作项目 Benchmark 证据。

## 验证

组件测试固定菜单顺序、含可选 effort 的精确投影路由、已本地化的任务处理级别、AA 与 fallback 依据标签、确切 AA 快照呈现、schema v1 回放、实时投影替换、仅级别变化的通知、减少动态效果行为，以及先停用 Auto 再执行手工选择的顺序。仓库内的无密钥完整 Web fixture 会对已构建 bundle 分别覆盖仅模型变化、仅 effort 变化、模型与 effort 同时变化和仅级别变化。它要求受影响值轨道滚动 1.2 秒、每个变化目标和 Auto 播放呼吸动画、未变化值保持静态，并要求中英文无障碍快照显示当前级别和依据。可选的跨仓库 beta fixture 会挂载外部 Auto 插件，并驱动真实浏览器、agent loop、Session 日志和请求头依次经过轻量、常规、深度与手工模式。它的常规级候选池证明先比较价格、再比较延迟；每个 Auto turn 都要求界面显示的路由与快照、持久化 selection 和有效请求配置完全一致。

## 考虑过的替代方案

**把 Auto 保留为全局启动选项。** 否决，因为它既不给用户提供会话级控制，也不提供请求确已变化的可见证据。

**在浏览器中维护推断的 Auto 状态。** 否决，因为客户端本地策略或乐观状态可能与 Host 决定分离。Session 投影是唯一展示的 Auto 事实。

**在模型菜单外增加单独的 Auto 控件。** 本原型否决该方案，因为提供方、模型和推理强度已有一个由 composer 持有的选择入口。拆分控件会隐藏它们的互斥关系，并重复状态展示。

## 后果

用户可以识别有效路由、所需处理级别和证据依据，而不会把深度等同于厂商 effort，也不会把 fallback 当成第四级。交互上，手工选择具有明确优先级；外部能力缺席时，标准菜单保持不变；现有 schema v1 Session 仍可读取。该 fork 在 `ui-model-selection` 中接受了 Auto 专用的可选类型、旧格式读取路径和命令桥；要让此集成离开固定版本实验，生产插件生态仍需上游提供方无关的贡献约定。
